# Merge into the current branch

## Prepare

Run `pnpm fixture:merge` and save the printed JSON. Every run creates new disposable repositories and bare remotes. `clean.path` and `conflict.path` each have a checked-out `main` diverged from `origin/main`. Each also has a `linked` worktree on a diverged tracking branch. The fixture prints the reviewed destination and source commit IDs and creates unrelated `notes.txt` and ignored `ignored.txt` files. Use a fresh undo directory for the app. Do not reuse the user's repository for fault injection.

Keep raw evidence from `git -C <path> status --porcelain`, `git -C <path> ls-files --stage`, and `git -C <path> rev-parse HEAD`. Resolve the worktree Git directory with `git -C <path> rev-parse --absolute-git-dir`; linked worktrees do not keep merge markers inside their `.git` file. Record screenshots from the browser and native app for the review, the operation strip in its conflicted and ready states, the operation inspector, the abort dialog, the conflict editor, and the refusal state.

## Select a source and review the plan

1. In a disposable fixture, run `git branch --unset-upstream` on the destination and create `refs/heads/selected` at the printed source. Right-click **selected** and choose **Merge into current branch…**. Confirm both full refs and IDs. Opening this menu must not check out the source or switch the active worktree. Cancel without changing HEAD or the index.
2. Select a linked worktree's uncommitted row, then select the source branch. Choose **Merge selected branch into current branch…** in the palette. Confirm the destination is still the linked worktree's branch. Repeat with `origin/main` as the source. Repositories that are not open must not offer the menu action. Busy, unattached, and active-operation destinations must disable it.
3. On a fresh fixture, create a source at HEAD and another at HEAD's parent. Each review must explain **Up to date** and disable Start. Create a source one commit ahead, review the **Fast-forward** plan, and click **Fast-forward**. Confirm only the destination ref advances to the reviewed source, status is clean, and no operation strip appears.
4. Hold a review request with the network debugger and switch repositories or active worktrees. Release the request. The review must stay closed and must not request a review for the new destination. Automated App tests exercise this delayed-response journey.
5. Try an ignored or untracked collision and a dirty tracked baseline before fast-forward. Start must refuse and preserve bytes. The real-Git tests exercise interrupted FastForwarding records immediately before and after Git publishes, ambiguous dirty/branch/marker states, and a failing post-merge hook. Ambiguity must preserve evidence and require attention. Active V1 sessions must reopen with their original pinned refs without resolving current tracking configuration, then write V2 on the next lifecycle action. Unknown versions must require attention.

## Review and finish a clean merge

1. Add `clean.path`. Click **Merge upstream…**, or choose it in the command palette. Confirm Source is `refs/remotes/origin/main`, Destination is `refs/heads/main`, and both full IDs match the fixture. Cancel once and confirm HEAD, status, and index are unchanged. Reopen and press Enter outside the Start button; it must not start a merge.
2. Click **Start merge**. Confirm the operation strip under the toolbar reads **Merging origin/main into main**, with the incoming ref in a violet chip and the current ref in a blue chip, and offers **No conflicts**, **Abort merge…** and **Finish merge**. Sides are named by ref, never ours or theirs. HEAD must still equal the original destination. The worktree Git directory's `MERGE_HEAD` must contain the reviewed source. Start must not appear in Undo.
3. Click **No conflicts** in the strip. The worktree row is selected and the inspector is titled **Merge**. **Into** shows `main` and **From** shows `origin/main`, each with its short ID, and the explanation says the merge commit gets both as parents and that `main` moves only when you finish. **Merged cleanly** lists `incoming.txt` and starts collapsed. Expand it and open `incoming.txt` in the existing diff viewer. The ordinary Commit/Amend and Stash controls must be absent. Selecting a commit in the history shows that commit in the inspector, not the merge. Record `git write-tree` for the Finish check.
4. **Commit message** shows the suggested message and reads **Suggested**. Type in **Merge description**. The summary keeps the suggested text and the hint reads **Edited · Use suggested**. Navigate away and return; the message must remain. Replace the summary with a space; hovering **Finish merge** says **Write a commit message first.** Click **Edited · Use suggested** to return to the suggestion, edit the description again, and click **Finish merge**. Verify `git show -s --format=%P%n%T%n%B HEAD`: exactly the original destination followed by source as parents, the recorded tree, and the submitted message. The strip closes and a completion notice names the commit. No push occurs, and lifecycle Finish has no Undo entry. The inspector footer said Finish and Abort cannot be undone.
5. Confirm `notes.txt` and `ignored.txt` retain their bytes. Inspect the graph and ahead/behind counts. Use Push only as a separate reviewed action if the journey includes publication.

## Resolve and recover a conflicted merge

1. Add `conflict.path`, review, and Start. Confirm the strip is amber, reads **1 file still has a conflict. Resolve it, then finish the merge.**, and shows one amber segment with **0 of 1 resolved**. **Finish merge** is disabled, and hovering it says **Resolve every conflicted file first.** Click the progress. The inspector lists `conflict.txt` under **Needs resolution · 1** labelled **1 conflict**, and its Files header reads **0 of 1 resolved**. Click the row to open it in the [existing text conflict editor](changes.md#resolve-a-stash-text-conflict). Inspect Base/Current/Incoming, use Pierre choices, then edit Result.
2. Click **Save result**. Verify saved bytes while `git ls-files -u` still contains the three stages. Click **Mark resolved** separately. The strip turns green, reads **All conflicts are resolved. Review the result, then finish.**, and **1 of 1 resolved**. The inspector moves `conflict.txt` to **Resolved · 1**. Undo once restores the stages and keeps the saved bytes, and the strip returns to amber. Undo again restores the original marker-bearing bytes. Redo twice restores both operations in order. Ordinary Commit and Amend remain unavailable.
3. Restart the bridge or native app with the same undo directory. Reopen this worktree. Confirm the session's exact IDs and resolution Undo history survive. The app must not run another merge. Existing unsaved editor/message drafts follow the normal draft-protection rules; process restart does not promise to persist unsaved text.
4. Advance `origin/main` through an explicit fetch: run `git --git-dir=<remote> update-ref refs/heads/main <original-source>^` against the fixture's bare remote, then click Fetch. This is a disposable remote rewrite used only by the fixture. Confirm the strip says the source branch has moved, and the inspector's **From** row still shows the original pinned source ID. Finish must remain available after resolving and staging. Verify the final second parent is that original source, not the fetched replacement.
5. On a fresh fixture, resolve and Save, then type more unsaved Result text. Finish must be disabled, and hovering it says **Save your unsaved conflict results first.** Open **Abort merge…** and click **Keep merging**; all text must remain. Open again. The dialog says `main` goes back to its original short ID exactly as before you started. **Discarded** names each saved resolution as **saved resolution** and each unsaved draft as **unsaved result draft**, and says a draft changed after the dialog opens is kept. **Kept** names the commit message draft, untracked files and ignored files. Click **Abort merge**. Abort restores the original HEAD and clean tracked state, clears only unchanged consented resolution drafts, retains the commit-message draft, and preserves unrelated untracked/ignored files. Resolution history is no longer replayable; earlier ordinary history is available again.

## Refusals and linked worktrees

1. On a fresh active conflicted session, edit `unrelated.txt` in a terminal and stage it with Git. Capture its bytes and index entry. Try Abort. The refusal must name `unrelated.txt`, keep MERGE_HEAD, and preserve that file and index entry. Repeat with an unstaged unrelated edit. Managed Stage/Unstage must also refuse paths outside the recorded merge footprint. Preserve or revert only this fixture edit externally before retrying Abort.
2. Before Start, test a tracked dirty file, a staged edit, an intent-to-add index entry, and a stale review after moving the source or destination. Each attempt must refuse without starting a merge. Place an untracked or ignored `incoming.txt` in the clean fixture and verify Start preserves its bytes and refuses the collision, including a case-alias spelling.
3. Add the fixture's linked working-copy path as a repository and open it. Start a second merge there. Resolve in one worktree, switch between the working copies, and confirm the other worktree has its own session and Undo history. Finish or Abort one; the other must stay active. From the other worktree, attempt to rename the active destination branch. It must refuse. The automated tests also exercise direct cross-worktree history requests and a forced duplicate branch checkout.
4. For unsupported binary, structural, symlink, filtered, or non-UTF-8 conflicts, confirm the existing editor gives an accurate external-resolution explanation. Resolve/stage with Git, refresh, then Finish through the managed session. Never offer an editable text result for unsupported content.
5. In a disposable active session, alter MERGE_HEAD or HEAD externally, then refocus the app to refresh merge state automatically. Confirm a red strip titled **Merge needs attention** with the readable preservation instructions and only **Copy recovery steps**, which copies them. There is no Finish/Abort continuation, and conflict Save and Mark resolved are disabled. A foreign operation with no managed session shows a neutral strip titled with Git's name for it, such as **A rebase is in progress**, reads **Started outside L1 Git. You can resolve files here, then continue or abort in your terminal.**, adds the commands Git names for a multi-commit sequence, and has no progress or actions. It must retain its existing conflict-editing route. Capture the session directory as evidence. Do not delete it to make the test pass. Automated real-Git tests cover interrupted Starting/Finishing/Aborting records and terminal retries.

## Hooks and activity exclusion

Use a fresh clean fixture with executable hooks. A refusing pre-commit hook must leave the session active and display its output. A hook that changes the staged tree, a failing post-commit hook, or a post-commit timeout after HEAD moves must report the observed landed commit with a diagnostic and refresh the graph. Confirm ordinary writes and update installation cannot race the lifecycle request, including while its final refresh is running. Repeat keyboard, focus, long-ref layout, and conflict-editor interactions in the native app.

Automated coverage lives in `write/merge/tests.rs`, the real bridge integration test, `MergeControls.test.tsx`, `OperationStrip.test.tsx`, `OperationInspector.test.tsx`, `inProgress.test.ts`, `App.merge.pin.test.tsx`, `draftTasks.test.tsx`, and `resolutionDrafts.test.ts`. These establish Git and component behavior; they do not replace the browser and native journey.
