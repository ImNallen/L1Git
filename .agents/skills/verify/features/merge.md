# Merge the current branch's upstream

## Prepare

Run `pnpm fixture:merge` and save the printed JSON. Every run creates new disposable repositories and bare remotes. `clean.path` and `conflict.path` each have a checked-out `main` diverged from `origin/main`. Each also has a `linked` worktree on a diverged tracking branch. The fixture prints the reviewed destination and source commit IDs and creates unrelated `notes.txt` and ignored `ignored.txt` files. Use a fresh undo directory for the app. Do not reuse the user's repository for fault injection.

Keep raw evidence from `git -C <path> status --porcelain`, `git -C <path> ls-files --stage`, and `git -C <path> rev-parse HEAD`. Resolve the worktree Git directory with `git -C <path> rev-parse --absolute-git-dir`; linked worktrees do not keep merge markers inside their `.git` file. Record screenshots from the browser and native app for the review, active panel, conflict editor, and refusal state.

## Review and finish a clean merge

1. Add `clean.path`. Click **Merge upstream…**, or choose it in the command palette. Confirm Source is `refs/remotes/origin/main`, Destination is `refs/heads/main`, and both full IDs match the fixture. Cancel once and confirm HEAD, status, and index are unchanged. Reopen and press Enter outside the Start button; it must not start a merge.
2. Click **Start merge**. Confirm the panel remains above the history, names the pinned pair, and offers **Finish merge** and **Abort merge…**. HEAD must still equal the original destination. The worktree Git directory's `MERGE_HEAD` must contain the reviewed source. Start must not appear in Undo.
3. Click **Review staged result and conflicts**. Inspect `incoming.txt` using the existing diff viewer. The ordinary Commit/Amend and Stash controls must be absent. The panel's **Reviewed staged tree** must match `git write-tree`.
4. Click **Use suggested message**, then edit **Merge commit message** and **Merge description**. Navigate away and return; the message must remain. Finish must remain disabled while the message is empty. Click **Finish merge** with the reviewed message. Verify `git show -s --format=%P%n%T%n%B HEAD`: exactly the original destination followed by source as parents, the reviewed tree, and the submitted message. The active panel closes and a completion notice names the commit. No push occurs, and lifecycle Finish has no Undo entry.
5. Confirm `notes.txt` and `ignored.txt` retain their bytes. Inspect the graph and ahead/behind counts. Use Push only as a separate reviewed action if the journey includes publication.

## Resolve and recover a conflicted merge

1. Add `conflict.path`, review, and Start. Open `conflict.txt`. Confirm the persistent panel reports one unresolved path. Use the [existing text conflict editor](changes.md#resolve-a-stash-text-conflict) to inspect Base/Current/Incoming, use Pierre choices, then edit Result.
2. Click **Save result**. Verify saved bytes while `git ls-files -u` still contains the three stages. Click **Mark resolved** separately. Undo once restores the stages and keeps the saved bytes. Undo again restores the original marker-bearing bytes. Redo twice restores both operations in order. Ordinary Commit and Amend remain unavailable.
3. Restart the bridge or native app with the same undo directory. Reopen this worktree. Confirm the session's exact IDs and resolution Undo history survive. The app must not run another merge. Existing unsaved editor/message drafts follow the normal draft-protection rules; process restart does not promise to persist unsaved text.
4. Advance `origin/main` through an explicit fetch: run `git --git-dir=<remote> update-ref refs/heads/main <original-source>^` against the fixture's bare remote, then click Fetch. This is a disposable remote rewrite used only by the fixture. Confirm the panel says the upstream moved, but still shows the original pinned source. Finish must remain available after resolving and staging. Verify the final second parent is that original source, not the fetched replacement.
5. On a fresh fixture, resolve and Save, then type more unsaved Result text. Finish must be disabled. Open **Abort merge…** and cancel; all text must remain. Open again and confirm **Discard merge and abort**. Confirm it describes saved resolutions and the listed unsaved drafts. Abort restores the original HEAD and clean tracked state, clears only unchanged consented resolution drafts, retains the commit-message draft, and preserves unrelated untracked/ignored files. Resolution history is no longer replayable; earlier ordinary history is available again.

## Refusals and linked worktrees

1. On a fresh active conflicted session, edit `unrelated.txt` in a terminal and stage it with Git. Capture its bytes and index entry. Try Abort. The refusal must name `unrelated.txt`, keep MERGE_HEAD, and preserve that file and index entry. Repeat with an unstaged unrelated edit. Managed Stage/Unstage must also refuse paths outside the recorded merge footprint. Preserve or revert only this fixture edit externally before retrying Abort.
2. Before Start, test a tracked dirty file, a staged edit, an intent-to-add index entry, and a stale review after moving the source or destination. Each attempt must refuse without starting a merge. Place an untracked or ignored `incoming.txt` in the clean fixture and verify Start preserves its bytes and refuses the collision, including a case-alias spelling.
3. Add the fixture's linked working-copy path as a repository and open it. Start a second merge there. Resolve in one worktree, switch between the working copies, and confirm the other worktree has its own session and Undo history. Finish or Abort one; the other must stay active. From the other worktree, attempt to rename the active destination branch. It must refuse. The automated tests also exercise direct cross-worktree history requests and a forced duplicate branch checkout.
4. For unsupported binary, structural, symlink, filtered, or non-UTF-8 conflicts, confirm the existing editor gives an accurate external-resolution explanation. Resolve/stage with Git, refresh, then Finish through the managed session. Never offer an editable text result for unsupported content.
5. In a disposable active session, alter MERGE_HEAD or HEAD externally, then refocus the app to refresh merge state automatically. Confirm **Merge needs attention**, readable preservation instructions, no Finish/Abort continuation, and disabled conflict Save and Mark resolved. A foreign operation with no managed session must retain its existing conflict-editing route. Capture the session directory as evidence. Do not delete it to make the test pass. Automated real-Git tests cover interrupted Starting/Finishing/Aborting records and terminal retries.

## Hooks and activity exclusion

Use a fresh clean fixture with executable hooks. A refusing pre-commit hook must leave the session active and display its output. A hook that changes the staged tree, a failing post-commit hook, or a post-commit timeout after HEAD moves must report the observed landed commit with a diagnostic and refresh the graph. Confirm ordinary writes and update installation cannot race the lifecycle request, including while its final refresh is running. Repeat keyboard, focus, long-ref layout, and conflict-editor interactions in the native app.

Automated coverage lives in `write/merge/tests.rs`, the real bridge integration test, `MergeControls.test.tsx`, `draftTasks.test.tsx`, and `resolutionDrafts.test.ts`. These establish Git and component behavior; they do not replace the browser and native journey.
