# Stage, unstage, commit, discard, and undo

## Sub-features

Row menus that stage, unstage, or mark a conflict resolved, **Stage all** and **Unstage all** list buttons, a diff that follows its file to the other list, toolbar **Undo** and **Redo**, Cmd/Ctrl+Z and Cmd/Ctrl+Shift+Z, the undo notice, and the stale-view and blocked-undo notices. The commit box under the lists with **Amend previous commit**, its per-worktree draft, Cmd/Ctrl+Enter, hook output and identity commands under the box, and undo and redo of commits. **Discard changes…** in Unstaged row menus, **Discard all…** beside the **Unstaged** heading, **Discard all changes…** in the palette, the confirmation dialog, and undo and redo of discards.

## How to get to it (user POV)

Add the fixture's `sync.dirty` path, the `sync-develop` worktree. Select its **Uncommitted changes** row. The inspector lists `README.md` under **Unstaged** with a **Stage all** button beside the heading. **Undo** and **Redo** sit in the repository toolbar to the left of **Fetch**.

## Driving it with T3 preview

Before and after each step, record `git -C <worktree> status --porcelain` and `git -C <worktree> ls-files -s` for every worktree you touch. Use a fresh `L1GIT_UNDO_DIR` per run, because the undo history survives restarts.

1. Hover `README.md` under **Unstaged** and click its **Options** button, or right-click the row. Choose **Stage**. Confirm the file moves to **Staged** with an **Unstage all** button and `status --porcelain` turns ` M README.md` into `M  README.md`.
2. Focus the **Staged** row and press Shift+F10. Confirm the same menu with **Unstage**. Press Enter. Confirm the file moves back and focus lands on its row under **Unstaged**.
3. Open `README.md`'s **Unstaged** diff, then stage it from its menu. Confirm the diff stays open with the **Staged** tag and the same hunk.
4. Hover **Undo** and confirm the tooltip names the entry, such as `Undo Stage README.md (⌘Z)`. Click it. Confirm the notice reads `Undid Stage README.md` with a **Redo** button, and the file is back under **Unstaged**. Press Cmd+Shift+Z with the history focused and confirm `Redid Stage README.md` with an **Undo** button. Run `ls-files -s` after each step and compare with the step before the write.
5. In a clone of the fixture's `repository`, edit two files and create an untracked one. Click **Stage all**. Confirm **Unstaged** empties and **Staged** lists three paths. Undo and confirm the notice reads `Undid Stage 3 files`.
6. Focus **Filter repositories and refs** and press Cmd+Z. Open the palette and press Cmd+Z in its field. Confirm no notice and no Git change.
7. With the worktree row shown, run `git add README.md && echo more >> README.md` in a terminal without focusing the app, then click **Stage all**. Confirm an error notice that starts `Could not stage README.md.`, `README.md` under both lists, and no change beyond the terminal's.
8. Stage a file, then run `git commit -m outside` in a terminal and click **Undo** without focusing the window another way. Confirm the notice says HEAD moved and that older changes stay blocked until this one can be undone, that the history now shows the `outside` commit, and that nothing changed. Run `git reset --soft HEAD~1` and click **Undo** again to confirm it works.
9. Make a merge conflict in a clone, choose **Mark resolved** on the conflicted path, then **Undo**. Confirm `UU` becomes `M ` and undo brings back the three stages in `ls-files -s`.
10. Open the palette. Confirm **Stage all** shows only with unstaged files, **Unstage all** only with staged files, and **Undo** and **Redo** only with an entry, titled with its label.
11. Stage a file, restart `pnpm dev`, and reload. Confirm **Undo** still names the stage.
12. Focus a staged row and press Cmd+Z. Confirm focus lands on the same path under **Unstaged**. Focus the notice's **Redo** and press Enter, then Enter again. Confirm the first redoes and the second undoes, because focus stays on the notice's button. Focus the toolbar's **Undo** and press Enter. Confirm focus stays on it. Confirm the toolbar buttons' accessible names name the entry, such as `Undo Stage README.md`.
13. This step restarts the bridge, and `pnpm dev` stops Vite when its bridge exits, so stop `pnpm dev` and run the two in separate terminals with the same ports and `L1GIT_UNDO_DIR`. Run `L1GIT_DEV_PORT=<dev port> L1GIT_BRIDGE_PORT=<bridge port> pnpm dev:web` in one and `L1GIT_DEV_PORT=<dev port> L1GIT_BRIDGE_PORT=<bridge port> L1GIT_UNDO_DIR=<undo dir> pnpm bridge` in the other, then reload the page. Stage `README.md` and click **Undo** so `Undid Stage README.md` shows. Replace the repository's `log.json` under `L1GIT_UNDO_DIR` with `{broken`, then focus the window. Confirm a second notice starting `Undo and redo are unavailable.` says how to start a new history, and **Undo** and **Redo** show `Undo is unavailable.` and `Redo is unavailable.` with the same advice as their tooltips. Click the notice's dimmed **Redo**, which does nothing. Put the file back and focus the window again to clear the unavailable notice. Focus the file's **Unstaged** row and press Cmd+Shift+Z. Confirm focus lands on its **Staged** row, not on the notice. Then stop the bridge with `kill "$(lsof -ti tcp:<bridge port> -sTCP:LISTEN)"` and focus the window. Start it again with the same `pnpm bridge` command, wait for `L1 Git development bridge on`, and press **Try again** on the error notice. Confirm the unavailable notice clears without another focus.
14. Step 13 leaves `README.md` staged, so unstage it from its menu first. Hold a write open with a slow clean filter, which Git runs while it stages the file. Run `git -C <worktree> config filter.slow.clean 'sleep 5; cat'` and `echo 'README.md filter=slow' >> "$(git -C <worktree> rev-parse --path-format=absolute --git-common-dir)/info/attributes"`, and add a second unstaged file with `echo note > <worktree>/notes.txt`. Stage `README.md` from its menu, then open `notes.txt`'s menu within five seconds. Confirm its item is dimmed and choosing it changes nothing. Afterwards run `git -C <worktree> config --unset filter.slow.clean` and `rm <worktree>/notes.txt`, then unstage `README.md` from its menu, so the worktree's only change is `README.md` again, unstaged.
15. Open a second repository, then return to this one. Run `git -C <worktree> commit --allow-empty -m outside` in a terminal. Suspend the bridge with `kill -STOP "$(lsof -ti tcp:<bridge port> -sTCP:LISTEN)"`, stage `README.md` from its menu, and click the second repository in the sidebar. Resume the bridge with `kill -CONT` on the same process. Confirm the app stays on the second repository after the write answers that HEAD moved, and that returning to the first shows the `outside` commit.
16. Record `git for-each-ref` and `git symbolic-ref -q HEAD` too from here on. Select the worktree's **Uncommitted changes** row. Stage `README.md`, type `Update readme` in **Summary**, and press Enter. Confirm nothing commits. Click **Commit**. Confirm `git log -1 --format=%s%n%P develop` prints `Update readme` and the ID of step 15's `outside` commit, the worktree row disappears because `README.md` was its only change, the new commit is selected, focus is on the history, and `develop` shows `2 to push` in the sidebar, for `outside` and the new commit.
17. Click **Undo**. Confirm `develop` is back at the old tip, `README.md` is staged, and `ls-files -s` matches the step before the commit. Select the worktree row and confirm **Summary** reads `Update readme` again. Click **Redo** and confirm `develop` points at the same commit ID as before the undo.
18. In a clone, stage a file, type a summary, focus **Amend previous commit**, and press Space. Confirm the fields fill with HEAD's message, the button reads **Amend**, and focus stays on the checkbox. Press Enter on the checkbox, in **Summary**, and in **Description**, and confirm nothing commits. Click it and confirm the new commit keeps the old parents and author.
19. In a clone, set `core.hooksPath` to a folder whose `pre-commit` prints `lint failed: TODO` and exits 1. Commit. Confirm the notice reads `Could not commit “…”. The pre-commit hook stopped the commit, so Git made no commit.`, the box shows `lint failed: TODO` under **The hook printed:**, the fields keep the draft, and nothing in Git changed.
20. Stage a file and show the box. Run `git commit --allow-empty -m other` in a terminal without focusing the app, then click **Commit**. Confirm the notice starts `Could not commit` and says the staged files changed, the lists reread, and only the terminal's commit changed Git.
21. Stop the bridge with `kill "$(lsof -ti tcp:<bridge port> -sTCP:LISTEN)"`. From the checkout, start the binary that `pnpm bridge` built with `HOME` set to an empty folder: `HOME=<empty folder> L1GIT_DEV_PORT=<dev port> L1GIT_BRIDGE_PORT=<bridge port> L1GIT_UNDO_DIR=<undo dir> ./target/debug/l1-git-dev-bridge`. `pnpm bridge` cannot run with that `HOME`, because Cargo looks for its toolchain there. Wait for `L1 Git development bridge on` and reload the page. In a clone, run `git config user.useConfigOnly true`, `git config --unset user.name`, and `git config --unset user.email`. Stage a file, type a summary, and click **Commit**. Confirm the box shows the two `git config` commands and nothing changed. Afterwards, stop that bridge and start `pnpm bridge` again as in step 13.

21. Record `git ls-files -s` and copy `README.md` with `cp -p`. Right-click `README.md` under **Unstaged** and choose **Discard changes…**. Confirm the dialog asks `Discard changes to README.md?`, lists `README.md`, and that **Cancel** has focus. Press Escape and confirm focus returns to the row. Open it again and click **Discard changes**. Confirm the worktree row disappears and the only change is ` M README.md` leaving the status. Focus the history and press Cmd+Z. Confirm the notice reads `Undid Discard README.md` and `cmp` finds the file identical to the copy.
22. Open the dialog again, run `git add README.md` in a terminal, then confirm. Confirm the notice starts `Could not discard README.md.`, says a chosen file changed, and only the terminal's staging changed Git.
23. In a clone, set up the files of `c2_discard_undo.sh`: a lossy clean filter, an LFS-style filter, an `eol=crlf` file with LF bytes, an executable bit turned on, a retargeted symlink, and an untracked file. Copy them with `cp -pR`. Click **Discard all…** and confirm. Click **Undo**. Confirm `cmp` matches every file, `stat -f %Lp` every mode, and `readlink` the link. Click **Redo** and confirm the status is clean again.
24. Discard a file, write new text into it in a terminal, then click **Undo**. Confirm the notice says the file was edited since, the file keeps the terminal's text, and nothing else changed.
25. In a clone, edit twelve files and click **Discard all…**. Confirm the dialog lists ten paths and `and 2 more`.
26. In a clone, add an untracked nested repository and change a submodule. Confirm neither row offers **Discard changes…** and that **Discard all…** says how many items it leaves.

## Gotchas

The row's **Options** button lives in the tree's shadow root and appears on hover or keyboard focus, so locate it inside `file-tree-container` or right-click the row instead. A write checks HEAD and the chosen paths' index entries, not file contents. Staging stages what is on disk when it runs, so a file edited after L1 Git read it stages the new bytes with no notice. Only an index or HEAD change, such as `git add` or a commit in a terminal, answers the stale-view notice. One undo history covers every worktree of a repository. Undo works in order, so an entry that cannot be undone blocks the older ones until it can. `@pierre/trees` row decorations cannot hold a button, so the row's write lives in its menu. A clone does not copy the fixture's repo-local identity, so set `user.name`, `user.email`, and `commit.gpgSign=false` in each clone before you commit. A commit that cleans the worktree removes its row and the box with it, so commit failures also show in the notice above the history. Discard keeps what it replaces in the undo folder, so use a fresh `L1GIT_UNDO_DIR` per run and delete it afterwards. The dialog closes before the discard runs, so a failure shows in the notice above the history. After a discard removes the focused row, focus goes to the page, so focus the history before Cmd+Z.
