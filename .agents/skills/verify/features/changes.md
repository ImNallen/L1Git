# Stage, unstage, commit, discard, and undo

## Sub-features

Row menus that stage, unstage, or mark a conflict resolved, **Stage all** and **Unstage all** list buttons, a diff that follows its file to the other list, toolbar **Undo** and **Redo**, Cmd/Ctrl+Z and Cmd/Ctrl+Shift+Z, the undo notice, and the stale-view and blocked-undo notices. The commit box under the lists with **Amend previous commit**, its per-worktree draft, Cmd/Ctrl+Enter, hook output and identity commands under the box, and undo and redo of commits. **Discard changes…** in Unstaged row menus, **Discard all…** beside the **Unstaged** heading, **Discard all changes…** in the palette, the confirmation dialog, and undo and redo of discards. Hunk bars and line ranges in a worktree diff that stage, unstage, and discard part of a file, the gutter plus button, the palette's line actions, and the stale-diff notice.

## How to get to it (user POV)

Add the fixture's `sync.dirty` path, the `sync-develop` worktree. Select its **Uncommitted changes** row. The inspector lists `README.md` under **Unstaged** with a **Stage all** button beside the heading. **Undo** and **Redo** sit in the repository toolbar to the left of **Fetch**.

## Driving it with T3 preview

Before and after each step, record `git -C <worktree> status --porcelain` and `git -C <worktree> ls-files -s` for every worktree you touch. Use a fresh `L1GIT_UNDO_DIR` per run, because the undo history survives restarts.

    ```sh
    cat > "$F/fakelfs-clean" <<'EOS'
    #!/bin/sh

    EOS

    #!/bin/sh

    EOS

    git config filter.fakelfs.required true; git config core.autocrlf input
    ```

## Gotchas

The row's **Options** button lives in the tree's shadow root and appears on hover or keyboard focus, so locate it inside `file-tree-container` or right-click the row instead. A write checks HEAD and the chosen paths' index entries, not file contents. Staging stages what is on disk when it runs, so a file edited after L1 Git read it stages the new bytes with no notice. Only an index or HEAD change, such as `git add` or a commit in a terminal, answers the stale-view notice. One undo history covers every worktree of a repository. Undo works in order, so an entry that cannot be undone blocks the older ones until it can. `@pierre/trees` row decorations cannot hold a button, so the row's write lives in its menu. A clone does not copy the fixture's repo-local identity, so set `user.name`, `user.email`, and `commit.gpgSign=false` in each clone before you commit. A commit that cleans the worktree removes its row and the box with it, so commit failures also show in the notice above the history. Discard keeps what it replaces in the undo folder, so use a fresh `L1GIT_UNDO_DIR` per run and delete it afterwards. The dialog closes before the discard runs, so a failure shows in the notice above the history. After a discard removes the focused row, focus moves to the row beside it in its list, the next one first, or to the history when the list is empty. Hunk bars are `@pierre/diffs` line annotations, so they sit in the page and a query for `.hunk-bar` finds them, but line numbers and the gutter plus button sit in the diff's shadow root. Pierre virtualizes long diffs, so a bar far from the viewport is in the DOM with zero size and no client rects until you scroll to it. Check a bar's size, not whether a query finds it. The plus button shows on a chosen range, and with a real mouse also on the hovered line.
