# Browse the commit graph

## Sub-features

Local and remote branch sections, branch filtering, the full graph of every branch, squash-merge edges, ref labels beside the graph, per-commit line changes, keyboard movement, branch highlight on ref hover, author nodes, jumping to a branch tip from the sidebar, windowed rows, loaded-history search, and local refresh.

## How to get to it (user POV)

Add the fixture's `repository` path. L1 Git opens on the repository screen. Expand **Local branches** and **Remote branches** in the sidebar. The graph always reads local and remote branches, tags, and HEAD. Columns are **Branch / Tag**, **Graph**, **Commit message**, and **Changes**. Internal refs and stashes are excluded.

## Driving it with T3 preview

1. Confirm nine loaded commits and six branches, with three local and three remote refs, and the summary label `All branches`. `origin/HEAD` must not appear.
2. Select the sidebar branch button named **feat/history**. Confirm the history still lists all nine commits, the row at the `feat/history` tip is selected, and the sidebar branch is highlighted. The toolbar still shows `main` as checked-out HEAD.
3. Select **origin/feat/remote-inspector**. Confirm the selected row's subject is `feat(inspector): show commit message and changed paths` and the inspector shows that commit. Confirm HEAD is unchanged with Git.
4. Click another commit row. Confirm the sidebar highlight clears. Click the same sidebar branch again and confirm its tip is selected again.
5. Confirm the merge has two graph edges to real parents and the graph rejoins their ancestor.
6. Confirm the squash commit `feat(search): search loaded history (#2)` has a solid edge down into the `feat/squashed` tip, `feat(search): match commit IDs`, besides its edge to its real parent. Its node still shows the initials `NA`, not a hollow merge circle.
7. Confirm the labels left of the graph. The squash commit row shows `main` with the checked-out icon and `+1` for `origin/main`. The `feat/squashed` tip shows `feat/squashed`. The `feat/history` tip shows `feat/history` and `+2` for the `detached-worktree` worktree and `origin/feat/history`. The theme commit shows the `v0.1.0` tag. Each badge's background is its row's lane color, and long names ellipsize inside the column. Each non-merge node shows the initials `NA`, and the merge node is a small hollow circle. Click a row's label or graph node and confirm that commit is selected.
8. Rest the pointer on the `feat/squashed` badge for half a second. Confirm the table gains the `highlighting` class and only the `feat/squashed` commits, its fork point `Merge branch feat/history`, and the squash commit `feat(search): search loaded history (#2)` keep the `lit` row class. Other rows, their **Changes** cells included, and graph paths with the `dim` class, fade to 0.3 opacity. The squash commit's edge into the `feat/squashed` tip stays lit and its edge to its real parent dims. Move the pointer off and confirm everything restores at once. Rest on the `main` badge, or its `+1` chip, and confirm the `main` first-parent chain stays lit while the `feat/squashed`, `feat/history`, and `feat/remote-inspector` commits dim. Leaving the badge before half a second never dims anything.
9. Focus **Search loaded history**. Search `graph`, then a known short SHA, then a nonexistent subject. Confirm matching rows, an explicit loaded-history label, and the empty result. Connections are hidden while filtering, and resting on a badge highlights nothing. With a search active, select a sidebar branch and confirm the search clears.
10. Clear search with **Clear history search** or Escape. Use **Filter repositories and branches** to find `remote-inspector`, then clear the filter.
11. Create an additional commit only in the fixture with Git. Click **Refresh**. Confirm it appears while the checked-out branch remains unchanged.
12. Switch rapidly between saved repositories. Confirm the final view belongs to the last selected root.
13. Read the **Changes** column. Each row shows green `+N`, red `−N`, and five diffstat blocks, and its accessible name reads `N lines added, N lines deleted`. Compare at least the root commit, the merge, and `feat(inspector): show commit message and changed paths` with the line totals of `git -C <repository> diff --numstat <first-parent> <oid>`, using the empty tree `4b825dc642cb6eb9a060e54bf8d69288fbee4904` as the root commit's base. Binary files count as 0 lines. In the fixture the root reads `+1 −0`, the merge `+4 −0`, and the inspector commit `+4 −2`. In a long history, scroll quickly and confirm the cells fill in once scrolling stops, with one `/api/run` request with `op: "lineStats"` instead of one per frame.

14. Click the root commit, then press Up. Confirm the history has focus, its `grid` reports the selected row in `aria-activedescendant`, and the inspector follows. Press K and J and confirm they move like Up and Down. Press Home, then End, then Cmd+Up and Cmd+Down, and confirm they select the newest and the root commit. Select `Merge branch feat/history` and press Shift+Down. Confirm the selection moves to its first parent, the `v0.1.0` commit, skipping the two `feat/history` commits. Press Shift+Down again for `docs: start the local Git fixture`, then Shift+Up twice, and confirm the selection returns through `v0.1.0` to the merge, along the straight graph line. Select the `feat/history` tip and press Shift+Down twice. Confirm the selection moves to `feat(history): add bounded repository history`, then to `docs: start the local Git fixture`. Press Enter on a commit with changes. Confirm the first path in the inspector's tree opens as a diff, and Escape returns to the history with focus and the same commit selected. Press Tab from the sidebar and confirm the history is one Tab stop. Focus **Filter repositories and branches**, type `jk`, and confirm the letters appear and the selection does not move.

To check scrolling, use a repository with more commits than fit on screen. Scroll the history away from a branch tip, then select that branch in the sidebar. Confirm the history scrolls so the tip row sits near the middle. Selecting a row that is already visible never scrolls. On the large fixture, press End and confirm the oldest loaded commit is selected and visible, then hold Down and confirm the selected row stays in view, scrolling one row at a time. Only the visible rows and a small margin exist in the DOM, and the table reports the full count in `aria-rowcount`.

## Gotchas

The graph holds at most the newest 50,000 commits. Past that, the summary reads `Newest 50,000 commits`, and selecting a branch whose tip is older shows the notice `<branch> is older than the newest 50,000 loaded commits.` Search covers loaded subjects, authors, emails, and IDs. It does not query older commits. A fixture used by another journey may have additional commits; recreate it to recover the nine-commit baseline. GitHub metadata displays `l1-family/l1-git` without a network request.
