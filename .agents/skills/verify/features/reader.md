# Read real repository data

## Sub-features

Canonical roots, linked worktrees, exhaustive HEAD states, local and remote refs, tags, worktree heads, bounded history, commit details, commit line counts, file patches, worktree status and patches, branch overviews, fetch, fast-forward, and transport validation.

## How to get to it (user POV)

Every Add, Refresh, and commit selection reaches the shared Rust Git core. Launch and interval fetches, **Fetch**, and **Fast-forward (N)** reach the overview, fetch, and fast-forward operations. The native `repository_run` Tauri command and the development bridge's `/api/run` route call the same `run` function.

## Driving it with the terminal

Run `cargo test --locked` to build temporary repositories and check normalization, distinct linked worktrees, fetched remote refs, tags peeled to their commits with non-commit tags skipped, history that reaches tag-only commits, attached and detached linked worktrees with only the opened root marked current, unborn and detached HEAD, the newest-50,000 history window, invalid input, first-parent merge details, squash merges paired with the branch tip they merged, line counts for root, edited, binary, empty, and merge commits with unreadable IDs left out, and file patches for text, binary, oversized, root, unchanged, and pathspec-magic paths. Worktree status tests read staged, unstaged, and both-sided edits, staged renames with later edits, all seven conflict kinds, untracked paths, paths with a space or a newline, a dirty submodule, and clean, detached, and unborn worktrees. HEAD matches the snapshot for a branch named `(detached)`, a HEAD pointing at a tag, and an unborn `(detached)` branch. Worktree patch tests read the staged and unstaged sides separately, a staged rename with its edits, a staged deletion with an untracked copy, every conflict kind, a submodule notice, untracked text, non-ASCII, binary, and oversized files, and staged files before the first commit. Untracked symbolic links show their link text and never their target, including links to directories, files, and FIFOs, and broken links. They reject paths outside the worktree, paths without changes on the requested side, and untracked nested repositories, and confirm neither read rewrites `.git/index` after an mtime-only change. The `sync` tests check branch roles and upstream states, fast-forwards of free, checked-out, linked, and partial-clone branches, and skips for moved, diverged, dirty, and mid-rebase branches. They also check per-remote auth failures and timeouts through fake ssh commands, and that two fetches of one repository never overlap. No external remote is contacted.

Run `pnpm test` to start a real isolated Rust bridge, create the deterministic fixture, parse HTTP responses with the frontend schemas, find a remote branch tip in the full history, read the fixture's tag and worktrees, read merge details, count lines for the root, merge, and inspector commits, and read text, binary, and root file patches. They read the `sync.dirty` worktree status, then build a repository with a staged rename, a both-sided edit, a conflict, and an untracked file, and parse its status and both sides of its patches with strict schemas. Against the `sync` fixture, they read local refs, fetch, fast-forward the ready branch, and receive skips for the dirty and diverged branches. A snapshot must answer while a slow fetch is in flight. The tests reject other origins, missing origins, unknown and missing fields, unknown operations, and the removed per-operation routes. A 400 names the field or operation at fault. `src/repositories.test.ts` checks the frontend's parsing of both transports with literal responses. Graph and recents tests run in the same command.

Run `pnpm build` and `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer pnpm tauri build --debug` for the frontend and native packaging checks.

## Gotchas

These checks prove data and build behavior. They do not prove visible tree expansion, dialog focus, native window chrome, or picker cancellation. The other feature journeys supply those checks. The core and bridge are the default Rust workspace members so Linux data tests do not need Tauri's native GUI dependencies.
