# Read real repository data and write the index

## Sub-features

Canonical roots, linked worktrees, exhaustive HEAD states, local and remote refs, tags, worktree heads, bounded history, commit details, commit line counts, file patches, worktree status and patches, branch overviews, fetch, fast-forward, guarded staging and unstaging with undo and redo, and transport validation.

## How to get to it (user POV)

Every Add, Refresh, and commit selection reaches the shared Rust Git core. Launch and interval fetches, **Fetch**, and **Fast-forward (N)** reach the overview, fetch, and fast-forward operations. The native `repository_run` Tauri command and the development bridge's `/api/run` route call the same `run` function. No UI stages yet, so the write, undo, redo, and undo history requests are reached only through the bridge or the IPC command.

## Driving it with the terminal

Run `cargo test --locked` to build temporary repositories and check normalization, distinct linked worktrees, fetched remote refs, tags peeled to their commits with non-commit tags skipped, history that reaches tag-only commits, attached and detached linked worktrees with only the opened root marked current, unborn and detached HEAD, the newest-50,000 history window, invalid input, first-parent merge details, squash merges paired with the branch tip they merged, line counts for root, edited, binary, empty, and merge commits with unreadable IDs left out, and file patches for text, binary, oversized, root, unchanged, and pathspec-magic paths. Worktree status tests read staged, unstaged, and both-sided edits, staged renames with later edits, a move added with `git add -N`, all seven conflict kinds, untracked paths, paths with a space or a newline, a dirty submodule, and clean, detached, and unborn worktrees. HEAD matches the snapshot for a branch named `(detached)`, a HEAD pointing at a tag, and an unborn `(detached)` branch. Worktree patch tests read the staged and unstaged sides separately, a staged rename with its edits, an unstaged rename, a staged deletion with the file left untracked, a copy that shows only its own section, a copy next to a type change, a type change on either side with both of its sections, every conflict kind, a staged submodule move as a gitlink diff, an unstaged submodule notice, untracked text, non-ASCII, binary, and oversized files, and staged files before the first commit. Untracked patches match `git add -N` followed by `git diff --full-index --no-textconv` byte for byte, including a file named `-`, an empty file, an executable, and a missing final newline. `worktree_patch_converts_line_endings_and_honors_attributes_like_git` holds that match under `core.autocrlf` set to `input`, `true`, and `false`, under `text`, `eol`, `text=auto`, `-text`, and legacy `crlf` attributes, and for `binary` and `-diff` files. `worktree_patch_shows_what_git_would_stage_under_any_attribute` holds it for clean filters, including one that adds text to an empty file, and for `diff.<driver>.binary`, `diff` on NUL content, an empty `-diff` file, `ident`, and UTF-16 `working-tree-encoding`. Other tests match Git for `core.bigFileThreshold` and `core.fileMode=false`, report the size of 256 MiB and 4 GiB files in under 2 s without running Git, and name a read failure for a file without read permission. `worktree_patch_names_a_required_filter_that_fails` returns Git's error, and `worktree_patch_returns_when_a_filter_leaves_stderr_open` returns within 5 s when a filter's background process holds stderr. Untracked symbolic links show their link text and never their target, including links to directories, files, and FIFOs, and broken links. A file swapped with links to an outside directory and an outside file during 200 reads never shows outside text or a raw OS error. `worktree_patch_never_shows_text_that_git_read_after_a_swap` swaps a parent directory for a link during a slow clean filter and expects the refresh error. They reject paths outside the worktree, paths with `.` or empty components, paths inside a `.git` directory, paths without changes on the requested side, and untracked nested repositories, and confirm neither read rewrites `.git/index` after an mtime-only change. The `sync` tests check branch roles and upstream states, fast-forwards of free, checked-out, linked, and partial-clone branches, and skips for moved, diverged, dirty, and mid-rebase branches. They also check per-remote auth failures and timeouts through fake ssh commands, and that two fetches of one repository never overlap. No external remote is contacted. `tests/deadlines.rs` lowers every read deadline to 1 s with `Coordinator::cap_reads` and checks that a clean filter that never finishes makes `worktreeStatus` and an untracked `worktreePatch` return `timedOut` with a message that names the read, between 1 s and 3.5 s, with no filter process left, even when the filter ignores SIGTERM. It also checks that a filter whose background process holds stderr open delays neither `worktreeStatus` nor a tracked `worktreePatch` past 3 s. `tests/slow_git.rs` puts a fake Git first on PATH that hangs for one commit, and checks the same for `commitDetail` while another commit still reads. `tests/stop_all.rs` checks that `stop_all_git` ends a hung read and a filter that ignores SIGTERM within 2 s, leaves processes it did not start running, and refuses to start Git afterward. `tests/stop_race.rs` calls `stop_all_git` while eight reads start Git and exits at once, 20 times, and expects no Git left.

Run `pnpm test` to start a real isolated Rust bridge, create the deterministic fixture, parse HTTP responses with the frontend schemas, find a remote branch tip in the full history, read the fixture's tag and worktrees, read merge details, count lines for the root, merge, and inspector commits, and read text, binary, and root file patches. They read the `sync.dirty` worktree status, then build a repository with a staged rename, a staged copy, a both-sided edit, a conflict, and an untracked file, and parse its status and both sides of its patches with strict schemas. A clean-filtered untracked file shows Git's filtered text. A second repository sends a submodule, a binary file, a file over 1 MiB, and an unreadable file across the bridge as `submodule`, `binary`, `tooLarge`, and `unreadablePath`. Against the `sync` fixture, they read local refs, fetch, fast-forward the ready branch, and receive skips for the dirty and diverged branches. A snapshot must answer while a slow fetch is in flight. A `writes` block clones the fixture per test, then stages, undoes, and redoes a file, refuses a stale view, repeats an undo harmlessly, and rejects unknown fields in a write, an entry, and an undo with 400. The tests reject other origins, missing origins, unknown and missing fields, unknown operations, and the removed per-operation routes. The list of operations in the unknown-operation message comes from `requestOps` in `src/repositories.ts`. A 400 names the field or operation at fault. A second bridge, started with a fake Git on PATH and `L1GIT_READ_DEADLINE_MS=1000`, returns `{"ok": false, "error": {"kind": "timedOut", ...}}` for a commit whose read hangs, then reads another commit. The hung Git starts with no signals blocked, and the read times out in under 2 s. A bridge with a read hung in that fake Git dies by SIGINT within 1 s of receiving it and leaves no Git process behind. `src/repositories.test.ts` checks the frontend's parsing of both transports with literal responses. Graph and recents tests run in the same command.

`tests/writes.rs` stages and unstages modified, deleted, untracked, renamed, conflicted, intent-to-add, and submodule paths, and paths with a space, a newline, `*`, and `[x]`, on born and unborn HEADs. Every write is undone and redone twice, and the index must match `git ls-files --stage --debug` before and after, flags included. It checks that a stale entry or a moved HEAD answers `staleView` and changes nothing, a held `index.lock` answers `lockHeld` and stays untouched, a conflict cannot be unstaged, a nested repository and an empty write are refused, and a file swapped for a folder is restored by undo. Redo restores a blob that `git gc --prune=now` deleted from the repository. The history keeps 100 entries, drops the redo side on a new write, spans linked worktrees, and refuses a store folder others can write. `tests/deadlines.rs` stops a stage that a clean filter never finishes at its 1 s write deadline, with no filter process, `index.lock`, `l1git-index.*`, or undo entry left. `tests/sync.rs` checks that a stage answers during a slow fetch of the same repository and waits for a fast-forward's ref move.

To drive a write by hand, start the bridge with `L1GIT_UNDO_DIR` pointing at a folder you own. POST `{"op": "worktreeStatus", "path": <worktree>}`, then POST `{"op": "write", "path": <worktree>, "operation": {"kind": "stageFiles", "entries": <the entries to stage>}, "expect": {"head": <the status head>}}`. The answer's `data.id` names the entry. POST `{"op": "undo", "path": <worktree>, "id": <id>}` and `{"op": "redo", ...}` with that id, and `{"op": "undoHistory", "path": <worktree>}` to read the next entries. Record `git status --porcelain` and `git ls-files --stage` before and after. A write leaves no `.git/index.lock` or `.git/l1git-index.*`. The undo dir holds one folder per repository, with `log.json` and an `entries/<id>/objects` folder per entry.

Run `pnpm build` and `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer pnpm tauri build --debug` for the frontend and native packaging checks.

## Gotchas

These checks prove data and build behavior. They do not prove visible tree expansion, dialog focus, native window chrome, or picker cancellation. The other feature journeys supply those checks. The core and bridge are the default Rust workspace members so Linux data tests do not need Tauri's native GUI dependencies.
